Scenario**Question:** What does a software team need to deliver a reliable room-booking system beyond the program code, and how should the team verify, document, deploy, and support it?**Users:*** Students who want to find and book available study rooms.* Administrators who manage rooms and review bookings.* Developers and testers who build and maintain the system.**Problem:** Students need a convenient way to find available study rooms and book them without conflicts. Administrators need to manage room availability and prevent bookings in blocked rooms.**Constraints:**1. **Technical constraint:** The system must prevent overlapping active bookings for the same room.2. **Time constraint:** **Fictional assumption:** The development team has four weeks to develop, test, document, and deploy the initial version.**Risk:** If the system incorrectly confirms two overlapping bookings, students may arrive at the same room at the same time, causing conflicts and reducing trust in the system.**Assumptions:*** **Fictional assumption:** The system is developed for a university with 20 study rooms.* **Fictional assumption:** Students and administrators access the system through a web browser.* **Fictional assumption:** Students log in using university accounts.* **Fictional assumption:** The initial version supports creating and cancelling bookings but does not include online payments or mobile applications.* **Fictional assumption:** The university provides a server for deployment and assigns an administrator to manage room availability.## 3. Appendix A — Initial outline1. **Understand customer needs:** Identify user requirements, define the system's scope, and agree on acceptance criteria with the university.2. **Prepare delivery documentation:** Create requirements, a system design, setup instructions, a user guide, and deployment documentation so that others can understand, install, and use the system.3. **Implement and test the software:** Develop booking and cancellation features. Test overlapping bookings, blocked rooms, invalid booking times, and permissions for students and administrators.4. **Deploy and verify the system:** Configure the server, database, environment variables, and access permissions. Run smoke tests after deployment to confirm that the main features work correctly.5. **Provide support and maintenance:** Monitor errors, back up booking data, fix reported bugs, document known issues, and provide a process for users to request help.## 8.
